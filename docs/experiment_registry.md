# 实验登记与迭代记录

本项目把候选方法和最终线上成绩分开记录。每个实验先写清楚假设、数据协议和比较基线，再运行一次；只有协议一致时才比较结果。

## 必填字段

| 字段 | 要求 |
|---|---|
| `id` / `family` | 唯一编号和方法族，避免重复试验 |
| `task` | A1/A2 或 B1/B2，明确任务边界 |
| `protocol_id` | 切分、特征版本、标签预算等组成的协议标识 |
| 假设 | 一句话写出可证伪原因 |
| baseline | 固定 anchor、指标和比较范围 |
| stability | 折数、负折、最弱分桶和盲半集检查 |
| decision | `adopt`、`reject` 或 `hold`，附原因 |
| official score | 仅填写平台返回分数，不能用 OOF 代替 |

## 迭代规则

1. 先复现 anchor，再只改变一个主要因素；每轮只运行一个实验。
2. B1 同时报告随机 OOF 和 train/test-like 验证，关注低度数节点与域偏移。
3. B2 按历史长度分桶，单独检查空历史；候选必须保留 Top1 和高置信行。
4. 只有平均提升、无负折、关键分桶不退化时才进入候选，否则记录失败原因。
5. 提交前运行格式审计；线上反馈回来后更新 `official_feedback.json`，不修改历史结果。

## 公开 smoke 实验

`public_synthetic_agent_smoke` 只验证 Agent 的规划、执行、指标解析和稳定性审计，不使用比赛数据，也不代表排行榜成绩。真实实验因依赖本地数据和缓存，不随公开仓库发布；原工作区可设置 `TIANCHI3_INCLUDE_LEGACY=1` 后启用。
