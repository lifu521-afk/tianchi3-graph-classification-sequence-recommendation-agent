# 技术路线

## 1. 赛题组成

天池三包含两个方向：

- **B1 节点分类**：输入稀疏节点属性和图结构，预测 8 类节点标签。
- **B2 金融场景序列推荐**：根据用户行为序列、用户属性和 item 属性，输出 Top10 推荐列表。

两个任务不能共用一套验证逻辑。B1 的主要风险是图结构和训练/测试节点之间的域偏移；B2 的主要风险是短历史、空历史和稀疏目标 item 导致的冷启动与排序不稳定。

## 2. B1 分类路线

1. 读取 CSR 格式的邻接矩阵与属性矩阵，保留原始方向，不额外假设无向或对称。
2. 构造原始属性、入边/出边/对称邻居聚合、二阶聚合和度数等特征。
3. 以 Ridge/Logistic Regression 作为稳定基线，比较图传播和图神经网络 challenger。
4. 使用随机 OOF 做初筛，再用交叉拟合的 train/test propensity 构造 test-like 验证。
5. 只有当平均分、最弱 test-like 分桶、嵌套留出和 bootstrap 稳定性都达标时才替换线上 anchor。

## 3. B2 推荐路线

1. 先分析 item 覆盖、历史长度、重复行为和空历史比例。
2. 以全局流行度、转移统计和重复偏好建立规则基线。
3. 将训练中出现过的目标 item 作为有限候选类别，用 MLP 序列分类模型学习序列统计特征。
4. 用 GRU 补充行为顺序信息，多 seed 集成降低方差。
5. 按历史长度设置 MLP/GRU 融合权重；后续在稳定神经基线上加入小权重规则分支和保守重排。
6. 以 NDCG@10、分桶表现、Top1 保护、空历史保护和提交格式校验作为发布门槛。

## 4. 更新迭代方法

每轮实验遵循：

```text
数据画像 -> 明确假设 -> 保留 anchor -> test-like 验证
-> 重复切分/置信区间 -> 预测差分审计 -> 合法性校验 -> 决定是否提交
```

线上成绩只记录为线上事实；本地 OOF、test-like 和候选结果单独标注，避免把离线增益写成线上提升。
