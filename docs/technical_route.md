# 技术路线

## 1. 总体框架

项目围绕两个结构化预测任务建立统一流程：

```text
数据画像 -> 稳定基线 -> 结构/序列特征 -> OOF 与 test-like 验证
       -> 候选实验 -> 差分审计 -> 提交校验 -> 线上反馈
```

重点不是堆叠模型，而是判断新增信号是否稳定、是否适合测试分布。

## 2. B1 节点分类

输入为稀疏节点属性和 CSR 图结构，输出测试节点类别。先保留原始有向关系，构造原始属性、入边聚合、出边聚合、对称邻居、多阶传播和度数特征；以 Ridge/Logistic 作为低方差 anchor，再比较图平滑和残差修正。随机 OOF 只用于初筛，最终还要检查 train/test 相似度、低度数节点和最弱分桶。

## 3. B2 序列推荐

输入用户行为序列、用户属性和 item 属性，输出 Top10。基线由流行度、转移概率、类别偏好、重复偏好和用户先验组成；MLP/GRU 用于学习序列表示，再按历史长度进行门控融合。验证时从训练行为中截断历史，单独报告空历史、短历史和长历史，避免完整历史造成乐观偏差。

## 4. Agent 迭代

Agent 按预算串行执行已登记实验，保存假设、命令、指标、失败原因和候选状态。只有在协议一致、平均提升、无负折且关键分桶不退化时才接受候选；官方榜单反馈单独记录，不能用离线分数替代。
