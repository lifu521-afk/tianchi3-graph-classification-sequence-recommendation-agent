# 项目能力与垂直方向研究规划

## 1. 项目定位

本项目不是单一模型脚本，而是一套面向稀疏监督任务的实验基础设施，覆盖图节点分类、序列推荐、可靠评估和实验控制 Agent。核心研究问题是：在反馈有限、分布可能变化的条件下，如何稳定迭代结构化预测系统。

## 2. 当前能力

### 图节点分类

- 读取 CSR 邻接矩阵和稀疏属性矩阵。
- 计算入边、出边、对称邻居和多阶传播特征，保留有向关系。
- 使用 Ridge/Logistic 内容基线，并叠加图平滑或残差修正。
- 按节点度数、训练/测试相似度和低置信样本分析误差。

### 序列推荐

- 处理原始序列、去重序列、重复次数、用户属性和 item 属性。
- 提供流行度、转移概率、类别偏好、用户先验和重复偏好规则。
- 提供 MLP、GRU，以及规则分数与神经分数融合。
- 按历史长度处理空历史、短历史和长历史用户。
- 检查 Top-K item 合法性、重复项、行顺序和模板一致性。

### 可靠评估

- OOF 用于候选筛选，test-like 验证模拟测试分布。
- 记录每折提升、最差分桶、盲半集结果和候选覆盖率。
- 使用 anchor 保护、零负折和字节级未修改任务检查降低提交风险。
- 将离线指标、候选结果和官方反馈分开保存。

### 实验 Agent

- 形成 `profile -> hypothesis -> run -> evaluate -> audit -> accept/reject` 闭环。
- 每轮运行一个注册实验，支持轮数、时间和无提升次数预算。
- 保存可恢复的 JSONL memory 与 state。
- 可选接入 OpenAI-compatible planner，但 planner 只能选择已登记实验。

## 3. 可承接的垂直项目

| 方向 | 预测对象 | 复用能力 | 主要新增工作 |
|---|---|---|---|
| 反欺诈/洗钱网络预警 | 客户、账户、商户节点 | CSR 图、入出边聚合、稳定性评估 | 时间窗图、标签延迟、可解释路径 |
| 供应链关系风险 | 企业节点或企业对 | 有向图传播、内容基线 | 企业属性、事件时间轴 |
| 电商/内容推荐 | 下一次点击或购买 item | 转移矩阵、GRU、Top-K 审计 | 召回、负采样、曝光偏差校正 |
| 金融产品推荐 | 用户下一步购买产品 | 用户先验、序列模型、冷启动分桶 | 风险等级、适当性和合规过滤 |
| 工业设备故障预测 | 设备、部件或工单节点 | 图结构特征、稀疏属性 | 传感器时序、故障时间窗 |
| 知识图谱实体分类 | 实体或关系类型 | 有向邻居聚合、内容/结构融合 | 文本编码、关系类型特征 |
| 学术合作/论文推荐 | 作者、论文或用户-论文序列 | 图传播、序列推荐 | 时间衰减、主题向量、去重 |
| 医疗事件风险研究 | 患者、诊疗事件节点 | 稀疏图、序列模型、分桶评估 | 时间因果切分、缺失机制建模 |
| 通用实验自动化 | 实验配置和候选模型 | Agent、协议管理、预算控制 | 元特征库、资源调度、结果数据库 |

## 4. 优先推进的三个方向

### A. 金融行为序列推荐平台

与当前代码最接近。先统一用户行为 schema，增加 Recall@K、MRR、NDCG、覆盖率和分桶指标；再加入候选召回、学习排序、曝光偏差校正和 A/B 接口。重点研究短历史用户依赖群体先验还是属性，长历史用户的重复偏好如何建模，以及融合门控能否跨时间稳定。

### B. 时序图风险预警

把静态 CSR 图改为按日期切片的动态图，训练只能使用预测时刻之前的信息，采用滚动时间窗验证。先比较内容模型、单向传播、双向传播和时间衰减，再引入事件序列编码。重点研究结构信号的有效时间、风险传播节点和 test-like 验证对未来退化的预测能力。

### C. 可审计实验 Agent

升级为通用实验服务：输入数据画像、候选注册表和资源预算，输出计划、日志、指标、失败原因和下一步建议。后续接入 SQLite/MLflow、多项目历史、GPU 资源估计和失败模式库，比较 Agent 与人工网格、随机搜索、贝叶斯优化的单位 GPU 小时收益。

## 5. 研究迭代路线

1. **工程收敛（1-2 周）**：统一 `fit/predict/evaluate` 接口，加入 schema 校验、随机种子、环境记录和 synthetic fixture。
2. **方法实验（3-6 周）**：图任务比较传播与残差门控；推荐任务比较规则、MLP、GRU、召回+排序和长度门控；统一报告均值、标准差、最差折和最差分桶。
3. **Agent 研究（7-10 周）**：注册表迁移 SQLite，设计收益、方差、成本、创新度联合评分，加入重复实验检测。
4. **垂直验证（11 周以后）**：选择公开金融推荐或时序图数据集，进行时间外推、冷启动、公平性和 Docker/CI 复现验证。

## 6. 必须补强的问题

- **时间泄漏**：垂直项目必须使用严格时间因果协议。
- **不确定性**：加入校准、置信区间和 abstain 策略。
- **可解释性**：输出关键邻居、路径、历史行为和类别依据。
- **公平与合规**：加入群体切片、敏感属性隔离、人工复核和审计日志。
- **线上闭环**：离线 Accuracy/NDCG 不能替代线上价值，需要延迟反馈、A/B 测试和回滚。

## 7. 项目边界

当前仓库适合作为研究原型、离线实验框架和论文复现基础，不应直接用于金融交易、授信、临床诊断等高风险自动决策。生产化前必须补充数据授权、隐私保护、时间切分、偏差评估、监控、人工审核和回滚方案。
